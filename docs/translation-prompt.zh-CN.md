# 对照文档生成提示词

复制下面的提示词发送给 ChatGPT，并将 `{文档名}` 替换为实际文件名。

---

你要为一个 Markdown 对照阅读器制作两份严格对应的文档：

1. 英文原版：{文档名}.en.md
2. 中文翻译：{文档名}.zh-CN.md

我接下来提供的内容可能是：

- 一段复制的英文文本；或者
- 一个公开访问的英文文档网址。

请按以下规则处理。

【英文原版要求】

1. 英文内容必须忠实于输入原文。
2. 不要总结、改写、润色或补充原文没有的信息。
3. 只允许清理网页导航、广告、页脚、Cookie 提示、重复菜单等非正文内容。
4. 将正文整理为规范的 Markdown。
5. 保留原来的标题层级、段落顺序、列表、引用、表格、代码块、图片和链接。
6. 如果输入是网址，请在文档最前面加入：

> Source: 原始网址

7. 如果无法完整访问网址，立即告诉我，不要猜测、补写或伪造缺失内容。

【中文翻译要求】

1. 按英文原版逐段翻译为自然、准确的简体中文。
2. 不要总结，不要省略信息，不要添加解释。
3. 英文一段必须对应中文一段。
4. 不得合并段落，也不得把一个段落拆成多个段落。
5. 标题、列表项、引用、表格行和代码块的数量及顺序必须与英文版一致。
6. 专业术语第一次出现时，可以使用“中文（English）”，之后使用中文。
7. 对没有合适中文译法的术语保留英文。
8. 如果英文版开头有 Source，中文版对应写成：

> 来源：原始网址

【必须原样保留的内容】

以下内容在中文版中也不得翻译或修改：

- 代码块
- 行内代码
- Shell 命令
- API 名称
- 函数名和变量名
- 文件路径
- URL
- 配置字段
- 参数名称
- 版本号
- 产品名称
- Markdown 链接目标
- HTML 标签

代码块的围栏、语言标识和内容必须完全一致。

【对照结构要求】

两份文档必须具有相同的内容块数量和顺序，包括：

- 标题对应标题
- 段落对应段落
- 列表项对应列表项
- 引用对应引用
- 表格行对应表格行
- 代码块对应代码块

即使中文表达较长，也不要改变段落边界。

【输出要求】

1. 创建两个独立、可下载的 Markdown 文件：
   - {文档名}.en.md
   - {文档名}.zh-CN.md
2. 不要把两份文档合并到一个 Markdown 代码块中。
3. 不要在文档正文中加入翻译说明、校对报告或额外注释。
4. 输出前自行检查：
   - 标题数量是否一致
   - 段落数量是否一致
   - 列表项数量是否一致
   - 代码块数量和内容是否一致
   - URL 是否一致
5. 如果内容太长，先告诉我建议如何按章节拆分，不要擅自截断文档。
